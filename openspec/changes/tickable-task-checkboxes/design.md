## Context

See proposal.md — Why. Implementation-relevant facts:

- The AST cache (`markdown.ts`) caches the transformed AST per document version; `@mdr/gfm` (priority 0) parses, `@mdr/shiki` (priority 10) rewrites code blocks in place. A new transformer between them (priority 5) sees the final task-list structure and its annotations are cached for free.
- mdast `listItem` nodes for GFM tasks carry `checked: boolean | null` and a `position` spanning the item's source (marker included, first character of the item). remark-rehype copies `node.data.hProperties` onto the rendered `<li>`, so annotations survive into the HTML without any reader-side pairing walk. The `<input type="checkbox">` itself is generated by remark-rehype and renders `disabled` — it cannot receive clicks until enabled.
- The reader renders a memoized HTML string via `dangerouslySetInnerHTML` and re-renders on every document text change (the text is the store snapshot).
- `useCodeMirror` (editor.tsx) creates the view once per document from `document.text` and only ever pushes changes (`document.setText` in its update listener). No code observes external `setText` today because the editor is currently the only writer.

## Goals / Non-Goals

**Goals:**
- Ticking is exact: one marker, in the clicked item's source span, nothing else.
- Zero new save/persistence paths — ticks are `setText` like any edit.
- Editor and reader stay consistent in split view.

**Non-Goals:**
- Clickable checkboxes in the CodeMirror editor.
- Task counts, progress indicators, or `[/]`-style partial states.
- Ticking for non-markdown document types.
- New settings.

## Decisions

### D1 — Annotate in a transformer, not in the reader

`@mdr/task-ticks` (priority 5) walks `payload.ast` once per parse and sets `data.hProperties = { dataTaskStart, dataTaskEnd }` on each `listItem` with `checked !== null`. The offsets land on the rendered `<li>` as `data-task-start` / `data-task-end`. Alternatives: a reader-side pass that walks the mdast for offsets and the hast for inputs in parallel (order-coupled double walk on every render, knowledge stranded in reader.tsx), or a whole-document regex at click time (would hit `[\s|x]` in code blocks and prose). The transformer is the platform's intended seam, runs once per version, and any future HTML consumer of the AST gets the annotations for free.

### D2 — Swap inside the item's source span

The click handler slices `document.text` between the item's offsets and replaces the first match of `\[( |x|X)\]` within that slice with `[x]` (tick) or `[ ]` (untick). The marker is always the first bracket pattern in an item's span (it directly follows the bullet), so first-match is exact, not heuristic. Uppercase `[X]` normalizes to `[x]` on tick and to `[ ]` on untick.

### D3 — Enabled state lives in the render pipeline; the reader element has stable identity

react-dom rewrites `dangerouslySetInnerHTML` on every commit even when the html string is unchanged, and the reader pane re-renders whenever pane focus changes (context) — which happens on mousedown, the instant a user clicks a checkbox. Two consequences drove the final design:

1. The enabled state must come out of the render pipeline, not be patched onto the DOM after commit. A post-commit enable pass is clobbered by the next commit (the pane re-render fires ~2ms into the click, replacing the checkbox), and a browser suppresses `mouseup`/`click` when the mousedown target is detached before mouseup. The reader's renderer therefore carries a small rehype transformer that strips `disabled` from checkbox inputs inside `@mdr/task-ticks`-annotated list items, making the emitted html carry the enabled state and stay byte-identical across unrelated re-renders.
2. The reader element itself is memoized (`useMemo` on the html string). Element identity is a React memo boundary: with the same element reference, React skips the subtree entirely, so focus-driven re-renders no longer touch the reader DOM at all. (Verified: react-dom writes innerHTML unconditionally for `dangerouslySetInnerHTML` props — string equality does not prevent the write; only skipping the subtree does.)

The delegated click listener is per document, attached in an effect keyed on `[document, html]` — on first render the container does not exist yet (html is null until the AST cache serves), so keying on `document` alone attaches nothing. The browser toggles the checkbox's `checked` property before dispatching `click`, so the handler reads it directly as the new state (inverting it would write the old marker back, a no-op).

### D4 — Editor syncs external changes via subscription

`useCodeMirror` subscribes to `document.subscribe` for the lifetime of the view. On notification, if `document.text !== view.state.doc.toString()`, the change did not originate in this view (view-driven edits call `setText` synchronously inside the update listener, so by subscription time the strings already match); dispatch `{ changes: { from: 0, to: doc.length, insert: document.text }, annotations: Transaction.remote.of(true) }`. `Transaction.remote` keeps external changes out of the undo history, satisfying the undo scenario. The subscription is created and torn down inside the same effect that owns the view.

### D5 — Native inputs, token styling

Keep the real `<input type="checkbox">` (keyboard Tab + Space for free, correct assistive semantics) and style it with accent/fill/separator tokens in `theme.css`, light and dark via the appearance switch. No custom div/button reconstruction.

## Risks / Trade-offs

- [Full-document replace dispatch in the editor resets CodeMirror internal state for large docs] → The dispatch only fires on external changes (rare, single on each reader tick); acceptable latency. If it ever matters, diff-based dispatch can be added later without changing the contract.
- [Reader re-render on tick rebuilds the whole HTML string] → Already the case for every edit from the editor in split view; no regression.
- [Scroll position across re-render] → The container element persists (only its innerHTML is replaced) and the tick does not change content height, so scroll is preserved.
- [AST annotations on a mutated shared AST] → The transformer runs once per parse before caching, matching how `@mdr/shiki` already mutates the payload in place.

## Migration Plan

Single-PR change; no data or format migration. Rollback is a revert. Order: taskTicks transformer → reader wiring → editor sync → styles → verification.
